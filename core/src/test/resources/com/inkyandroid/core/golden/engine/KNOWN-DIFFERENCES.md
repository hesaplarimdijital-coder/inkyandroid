# The engine against the reference inklecate: what is compared, and where they differ

The files in `expected/` are what the official **inklecate 1.2.0** printed; `EngineGoldenTest` holds
`com.inkyandroid.core.engine` (the library blade-ink 1.3.3 behind our own types) to them. They are
generated by `core/src/test/golden/engine/generate.py`, whose header describes their format.

Every difference the test accepts is listed here with its reason. The ones that concern single
texts or inputs are also in `known-differences.json`, which the test reads: it accepts exactly
those, and fails when one of them no longer occurs.

## What is compared

For each of the 25 bundled samples (Inky's "longer ink snippets", `theintercept` among them) and each
of the 22 purpose-written projects in `cases/`:

| What | How |
| --- | --- |
| Compile messages (errors, warnings, TODOs) and whether the ink compiles | text, file and line of every message |
| The compiled story (`inklecate -c -o`) | as a tree (see 4) |
| Statistics (`inklecate -s`) | all seven numbers, also for ink with errors |
| Play transcripts (`inklecate -ckjp`, the protocol Inky speaks): always the first choice, two random walks through the choices for every sample, and fixed choice sequences for the cases | every line, its tags, the runtime messages after it, the choices with their tags, the end |
| Typed input in play mode (what Inky's watches send) for the case `watch` | the printed value or the error |

The cases: `issues-parse`, `issues-meaning`, `issues-warnings` (every kind of message, in the main
file and in included files, a missing and a recursive INCLUDE), `nested-includes`, `tags` (global,
line and choice tags), `glue`, `weave`, `tunnels-threads`, `functions` (also EXTERNAL with an ink
fallback), `external-missing`, `lists`, `sequences` (stopping, cycle, once-only, sticky and
fallback choices, read counts, TURNS_SINCE), `shuffle`, `variables-math`, `floats`,
`runtime-errors`, `divide-by-zero`, `loop-output`, `loop-silent`, `deep-nesting`, `watch`,
`unicode` (Turkish text, emoji, CRLF line ends).

93 transcripts are compared event by event and are identical apart from what follows.

## Differences in what the player sees

1. **Floats are printed the Java way.** `3.0` for `3`, `2000000.0` for `2000000`, `1.0E8` for
   `100000000` (case `floats`, two lines). The library prints a float with `Float.toString`, the
   reference with .NET's shortest form. Values with a fraction print the same (`0.5`,
   `0.33333334`). It cannot be corrected outside the library, and the port uses the library as
   published.
2. **Random numbers differ.** `RANDOM`, shuffles (`{~a|b}`) and `LIST_RANDOM` draw from
   `java.util.Random` here and from `System.Random` in the reference, so the same seed gives other
   numbers (cases `shuffle`, `pontoon_example`, `swindlestones`: their transcripts are not
   compared, and the test checks that they do in fact differ). The web player (inkjs) has a third
   generator. Within the engine a playthrough is repeatable: the seed is part of its state.

## Where the reference fails and the engine answers

3. **Nesting deeper than the parser's stack** (24 nested `{…}`; case `deep-nesting`): inklecate
   dies with `Unhandled exception … Stack overflow in parser state`, and Inky shows "the ink
   compiler crashed". The engine reports one error without a line: "The ink is nested too deeply
   for the compiler …". Statistics: none from either.
4. **Integer division by zero** (case `divide-by-zero`): inklecate dies with `Attempted to divide
   by zero`. The engine ends the turn with `StopReason.EngineFailure` and the message `/ by zero`;
   the lines before it are the same.
5. **A story that never stops.** With output (case `loop-output`) inklecate prints for ever
   (slowing down after 1,000 lines); the generator stops reading after 300 lines, and the engine,
   given the same limit, produces the same 300 lines and stops with `StopReason.LineLimit`.
   Without output (case `loop-silent`) inklecate goes silent for good; the engine stops with
   `StopReason.TimeLimit`.
6. **Typed input** (case `watch`; five inputs): `x == 15` and `x +` kill inklecate (its play-mode
   grammar tries an assignment first, and a parse error there is fatal); the engine answers `true`
   and reports the parse error. A read count of zero (`some_knot`) prints nothing in inklecate and
   `0` here. A function call (`double(x)`, `"{double(x)}"`) never returns in inklecate, because it
   resolves the call inside the typed expression itself; the engine answers `30`. The other twelve
   inputs give the same value or the same error.

## Same meaning, different form

7. **Order of compile messages.** `inklecate -j` lists author's notes, then warnings, then errors;
   the engine keeps the order in which the compiler found them. Compared as sets.
8. **The compiled story's bytes.** As a tree the stories are identical for all 41 projects that
   compile, with three allowances: the order of an object's keys (the library writes named content
   and list definitions in hash order); the spelling of a float (`1.0E8` for `100000000.0`; whether
   a number is an int or a float must agree); and the order of the global variables' declarations
   inside `global decl` (hash order again; they are independent, since ink refuses a global whose
   initial value refers to another variable). inkjs loads these stories and plays them like the
   reference (`check-web-export.js`).
9. **A missing EXTERNAL binding** (case `external-missing`): inklecate prints the error and its
   process ends; Inky shows the error and "End of story". The engine's turn carries the same
   error and `ended`.
10. **"Recursive INCLUDE detected"** names the open file by its absolute path in inklecate, which
    here is the generator's temporary folder; the generator removes that folder from the message,
    leaving the project path, which is what the engine prints.

## Where the engine is right although the library is not

11. **`FLOOR`, `CEILING`, `INT` of a float and `FLOAT` of an int.** Stock blade-ink 1.3.3 throws
    `ClassCastException` for the first three and returns an int for the fourth (`FLOAT(3) / 2` is
    `1`). The engine replaces these four entries of the library's function table when it starts
    (`InkyPackageAccess.kt`), and then agrees with the reference (cases `floats`, `variables-math`;
    `NativeFunctionsTest`).

## Not compared, by design

- **Jump to source.** Inky asks inklecate for a character offset counted over the whole session,
  and the two sides count differently, so the answer drifts. The engine instead knows, for every
  character of every line, the file and line that produced it (`StoryLine.spans`); its own tests
  cover that (`PlaySessionTest`).
- **Message order within one line.** Runtime errors and warnings raised by one line are compared
  as a set (inklecate prints errors first).
